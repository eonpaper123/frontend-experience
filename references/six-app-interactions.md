# Six App Interaction Patterns

Use these patterns to make an action's feedback feel connected from input through its real outcome. The example durations, counts, and geometry are starting points rather than product defaults. Apply [stateful motion](../SKILL.md#preserve-continuity-in-stateful-motion) and the relevant [Advanced Interaction Techniques](../SKILL.md#advanced-interaction-techniques) entry first.

| Pattern | Interaction contract | Acceptance focus |
| --- | --- | --- |
| **DONE BURST** | Keep the action in one control: press or squeeze, draw its check, then emit a brief particle burst only when the operation succeeds. A 500-700ms sequence and 8-12 particles are example values. | Pending is not success. Prevent duplicate activation, expose the authoritative result, and keep the mark and particles decorative. Retarget or stop motion cleanly if the action is interrupted. |
| **LINKED STATE** | Derive the checked item, progress, displayed count, and any coordinated background change from one authoritative selection or completion state. | Every representation updates from the same committed value; motion never becomes a second source of truth. Reduced motion still exposes the same result. |
| **STACK FAN** | Give cards one stable identity across collapsed and expanded layouts. One activation fans them into readable positions, and the reverse action restores the stack. | Preserve logical reading and focus order, keep content usable in both states, and verify rapid open and close interruption. For geometry and staggering, reuse [FAN](../SKILL.md#advanced-interaction-techniques). |
| **SNAP CARDS** | Let native CSS scroll snapping settle the selected card. Draw its associated SVG timeline for the selected content only after scrolling ends. `scrollend` is a web event, not a native Mini Program guarantee. | Verify actual target support for [`Element: scrollend`](https://developer.mozilla.org/en-US/docs/Web/API/Element/scrollend_event) and CSS [scroll snapping](https://developer.mozilla.org/en-US/docs/Web/CSS/scroll-snap-type). Keep native scrolling and snap as the owner; do not add a second custom inertia or snap controller. |
| **INERTIA WHEEL** | Let drag release into velocity decay and then settle onto one valid value. Out-of-range motion may compress elastically and return to the bound. Keep the selected value authoritative. | Reuse the [INERTIA](../SKILL.md#advanced-interaction-techniques) reference parameters as examples, not defaults. Give either native scrolling or the custom gesture and inertia controller sole ownership; do not layer both. Provide keyboard value changes and visible focus. |
| **CIRCLE REVEAL** | Start a circular reveal at the activating point, transition to the destination state, and reverse toward the originating control on return. | Verify [`Document.startViewTransition()`](https://developer.mozilla.org/en-US/docs/Web/API/Document/startViewTransition) support on the actual web target. This web API is not a native Mini Program capability; choose the target platform's implementation explicitly, without an automatic fallback. Preserve focus transfer, back navigation, and interruption behavior. |

For every pattern, keep keyboard and touch operation, visible focus, and final-state semantics intact. Cancel or retarget an active transition when newer input changes its target. Honor reduced motion with a direct or simpler state change while retaining the same result. Judge success from the real operation outcome, not from an optimistic animation. Check web API compatibility and Mini Program capabilities on the actual target; do not assume parity or switch to a fallback automatically.

For a circular reveal, measure the origin in the animated surface's coordinate space and use the distance to its farthest corner as the covering radius. Keyboard activation uses the invoking control's measured center rather than a stale pointer position. Recompute geometry if the surface changes before returning.

## Provenance and limits

The pattern set was inspired by Xigua Tongxue's ("Watermelon Classmate") public demonstration, "Six interactions that make AI-built apps and Mini Programs feel more refined." The implementation contracts are independently written and use the linked platform documentation where a named web feature matters. This repository includes no source media, third-party implementation code, or assets. The reference does not claim a frame-by-frame review, rendered component, target-platform test, or universal timing and geometry values.
