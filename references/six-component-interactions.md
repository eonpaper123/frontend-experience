# Six Component Interaction Recipes

Use these as behavior-shape references for app and Mini Program components, then fit them to the product's established visuals, state model, platform semantics, and motion tokens. They are independent text summaries of interaction demonstrations, not implementation source; shown values such as `15–21pt` are examples, not global constants. No source video or assets are included.

| Recipe | Source shape | Business boundary and acceptance |
| --- | --- | --- |
| Multi-select filter tags | Selection grows a left check, fills the background, expands width, makes adjacent tags yield, and bumps the count. | One authoritative selection set drives tags and count; verify add/remove, rapid changes, wrapping, keyboard/touch operation, focus, announced count, interruption, and reduced motion. |
| Removable inline tags | Activating × shrinks the tag to a dot, fades it out, slides following tags into the gap, and lets the container height contract. | Remove only after the action commits; move focus predictably to the next tag, previous tag, or input and announce the removal. Verify first/last tags, wrapping, repeated deletion, interruption, and reduced motion. |
| Caret-anchored suggestions | A popover opens at the active caret, filters as text changes, inserts the choice as an inline token, and closes back into the text flow. | Preserve native editing and combobox keyboard behavior: do not query or commit mid-IME composition; support arrows, Enter, Escape, pointer input, and focus return. Bind results to the current query/range and ignore stale async responses before inserting the token. |
| Horizontal size scrubber | The selected value stays centered and highlighted, outer values fade, dragging changes the content size live, and release snaps to the nearest step. | Keep a semantic slider/value as the source of truth with named min/max/step; provide Arrow/Home/End or platform-equivalent controls and a non-gesture path. Verify bounds, drag reversal, release snap, keyboard parity, interruption, and reduced motion. |
| Press-point tilt | Press location controls a bounded tilt and slight scale-down while the glow gathers under the contact; release restores card and light. | Use the stateful-motion “depth follows input” contract with one owner for tilt, scale, and light; capture/cancel pointer input safely, keep press feedback separate from action commit, and provide visible keyboard/focus and reduced-motion states. |
| Hold-to-record bar | Holding the microphone expands the two-button group into a recording bar, a real audio waveform responds to sound, + morphs to cancel, and release returns the compact group. | Request microphone permission at the boundary and show pending, denied, active, cancel, preview/commit, and error states. Call a waveform “live” only when driven by the acquired audio stream; decorative waves are not recording proof. Release may end the hold and restore the container, but must not silently auto-send—commit and cancel stay explicit and accessible without a long press. |

## Shared rules

- Apply the existing stateful-motion contract first: define source/destination, anchor, authoritative state, interruption, reverse/settlement, and explicit commit/cancel outcomes. Reuse [component motion tokens](component-motion-tokens.md); do not copy the demonstration's sizes, timings, colors, or type range as defaults.
- For inline editing, keep the same invariant as the OTP/input-state recipe: native value, DOM/focus order, keyboard behavior, and authoritative status outrank visual motion. Borrow Advanced Interaction Techniques only when its mechanism actually matches (for example INERTIA after a scrubber fling or interruptible long press); do not import unrelated thresholds.
- Morphicons may own a compatible glyph transition such as + → ×, but never the container expansion, layout reflow, gesture, recorder lifecycle, or product state. Verify real touch and keyboard/non-gesture paths, reduced motion, rapid interruption, and data-backed claims on the target runtime.
