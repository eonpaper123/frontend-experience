# Profile cards: twelve composition references

Use for people, team, speaker, or personal-profile surfaces when composition is undecided. These twelve composition patterns are independent text summaries of visual examples attributed to YUNORA. No source images or assets are included, and the patterns are not tested conversion or recognition claims.

## Select by information priority

| Layout | Relationship to borrow | Check before using |
| --- | --- | --- |
| Portrait above | Large upper portrait, name and role below | Does image recognition deserve more space than biography? |
| Text-image halves | Text left, portrait right, approximately equal areas | Let real text length and mobile reading order determine proportions. |
| Centered avatar | Circular avatar and centered identity | Keep longer biographies readable; use consistent hierarchy across a team. |
| Photo first | Dominant photo with a distinct information strip below | Retain a legible identity strip at every crop. |
| Bio and data | Introduction above, supporting metrics below | Use verified metrics with meaningful labels, never invented credentials. |
| Floating label | Opaque identity label overlaps the photo | Reserve room for long names and avoid covering important portrait content. |
| Side-by-side | Portrait left, identity and description right | Stack deliberately at narrow widths; do not enforce 1:1 everywhere. |
| Spine name | Rotated name in a narrow side rail | Rotation is not automatically appropriate vertical typography; preserve logical text order and legibility for the actual language. |
| Name over photo | Name overlays a quiet dark area | Test actual image crops and contrast; a different photo may require different placement or a text surface. |
| Quote first | Large viewpoint, subordinate portrait and attribution | Only use a supplied or verified quote; keep identity discoverable. |
| Narrow portrait | Small arched portrait surrounded by whitespace | Preserve recognition and useful content rather than empty space alone. |
| Name and expertise | Identity followed by a short expertise list | List genuine capabilities; arrows imply real destinations, not decorative fake controls. |

## Delivery rules

1. Choose the primary job: identify the person, compare team members, understand expertise, or open a profile/contact action. Borrow one composition that serves it; twelve alternatives do not require twelve components.
2. Black-and-white photos, large serif names, and generous whitespace are this tutorial's style, not global defaults. Red notes, pointing arrows, and handwritten headings outside the cards are teaching annotations, not product chrome. Preserve the project's brand and typography.
3. Use genuine identity, role, biography, quotes, and evidence. The category → name → role → summary → action hierarchy is a useful option, not a requirement to invent missing fields. Reference portraits and tutorial images are not implicitly licensed production assets.
4. Keep name and biography as semantic, selectable text. Use actual links/buttons with accessible names and visible focus; do not nest interactive controls inside a whole-card link. Decorative arrows are not substitutes for labels or destinations.
5. Verify with long and multilingual names, real portrait focal points, text zoom, keyboard order, and actual mobile widths. Preserve image aspect ratio/layout stability and appropriate alternative text; inspect text-over-photo contrast at every supported crop. An attractive reference is not runtime acceptance.
